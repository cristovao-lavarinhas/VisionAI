Uma caixa diz onde. Uma frase diz o quê.

O VisionAI corre dois modelos sobre o mesmo ficheiro: o YOLOv8 devolve caixas, classes e confianças; o Florence-2 devolve a cena em linguagem natural. As duas leituras não competem — ficam lado a lado no mesmo JSON. Funciona sobre imagem e sobre vídeo, com os modelos a correr localmente.

Dois modelos

Geometria de um lado, linguagem do outro.

A divisão de trabalho é o projeto inteiro. Um dos modelos sabe apontar, o outro sabe descrever, e nenhum faz bem o trabalho do outro.

Geometria

YOLOv8

Para cada objeto devolve uma classe, uma confiança e quatro coordenadas. Barato de correr.

  • Limiar de confiança de 0,1 a 1,0
  • Pesos yolov8n.pt versionados no repo
  • Corre em todos os frames de vídeo
Linguagem

Florence-2

Devolve texto sobre a cena. É o modelo caro — e é isso que molda o processamento de vídeo.

  • microsoft/Florence-2-base-ft
  • Arquitetura vem do repo do modelo, via trust_remote_code
  • float16 com CUDA, float32 em CPU

O Florence-2 não tem uma saída só — recebe uma tarefa e responde em conformidade. A app usa quatro:

TarefaPara quê
<MORE_DETAILED_CAPTION>Descrição longa da cena inteira
<OD>Deteção pelo lado do Florence-2, para comparar com a do YOLO
<DENSE_REGION_CAPTION>Uma legenda por região, não uma por imagem
<CAPTION>Versão curta, usada nos frames de vídeo
Vídeo

O custo é que manda no ritmo.

Correr o Florence-2 em cada frame seria insustentável, e desnecessário: a cena não muda de frase de um frame para o outro. Por isso os dois modelos andam a cadências diferentes.

YOLO — todos os frames Florence-2 — a cada N frames (15 a 90, 30 por omissão)

Nos frames intermédios a última legenda é reutilizada e gravada na imagem. Se uma chamada ao Florence-2 falhar, o frame não fica sem legenda: mantém a anterior e o processamento segue em vez de rebentar a meio de um vídeo longo.

A legenda é quebrada por palavras à largura do frame e cortada às três linhas, sobre um retângulo opaco — nunca sai fora da imagem, seja qual for o tamanho do vídeo.

Saídas

Tudo o que sai, sai em ficheiro.

Nada fica preso ao ecrã. Cada análise produz um JSON, e o vídeo sai também como MP4 com as anotações gravadas na imagem. 

// imagem, modo híbrido
{
  "yolo_deteccoes": {
    "total_objetos": 3,
    "classes": { "person": 1, "car": 1, "traffic light": 1 },
    "deteccoes": [
      { "classe": "person", "confianca": 0.94, "bbox": [140, 140, 216, 298] }
    ]
  },
  "florence_analise": {
    "descricao_detalhada": "...",
    "objetos_detectados": { /* <OD> */ },
    "regioes_densas": { /* <DENSE_REGION_CAPTION> */ }
  }
}

No vídeo, o JSON é uma entrada por frame — índice, tempo em segundos, contagem de objetos, contagem por classe e a legenda em vigor — e a app mostra ainda o total de objetos, a média por frame e quantos frames foram analisados.

Correr

Dois comandos.

pip install -r requirements.txt
streamlit run app.py

Abre em localhost:8501. Os pesos do YOLOv8 nano estão no repositório; o Florence-2 é descarregado do Hugging Face na primeira utilização, cerca de meio gigabyte, uma vez só. Sem GPU corre à mesma, em float32 sobre CPU — mais lento, mas funciona.
